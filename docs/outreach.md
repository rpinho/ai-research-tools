# Outreach: draft, lint, approve, send

The outreach module never sends or fetches a message. It records a local lifecycle: draft, lint, approve, sent, reply, close or drop. Sending belongs to a separate tool and requires the operator's authorization for the actual message.

Set `RH_CONTACTS` to a private JSON file containing an array of objects with a nonempty `name` string. Names must be unique ignoring case. An optional `language` field holds the recipient's language as a code such as `pt`; unset or `en` means English and changes nothing. Extra fields may hold addresses for your separate sending tool; the harness uses names and that one field. Nothing in this repo contains contacts. Do not commit that file. Ledger metadata rejects email-address-shaped strings; draft bodies remain private files.

Set `RH_VOICE_COMMAND` to a shell-quoted executable and arguments. It receives the draft on stdin; lines starting `FAIL:` or a nonzero exit refuse lint. It is executed as an argument vector without a shell. For a social reply, the harness appends `--reply`. A missing checker refuses. No personal voice policy is provided. The tiny checker under tests is a synthetic fixture, not a writing standard.

`OUTREACH.toml` sets question limits and follow-up timing. Optional `science_checks = true` invokes `RH_SCIENCE_CHECK_COMMAND`, which receives JSON with `text`, `language` and `attachments` on stdin and uses the same failure convention. That replaces an installation-specific Python import. A checker that ignores `language` is unaffected by its arrival.

**Two-language email.** When a recipient's `language` is not English, that language is the default for the whole email, and the email opens and closes in it. English is required only where the content is technical: numbers, variables, equations, methods, measurements. Attachments are always English. The rule holds even for a recipient who writes their own science in English. Lint fails a technical paragraph in the recipient's language, an opening or closing that is not in it, and an attachment that is not English; ordinary prose in English anywhere is a warning, because it belongs in their language too. A paragraph counts as technical when it carries a statistic, a maths symbol, a variable-like token, two numbers, a number beside result vocabulary, or a dense run of technical terms. One number is not enough ("thanks for the 20 minutes"), and neither is the vocabulary alone ("a separate model re-checked the result" is prose).

Language identification is a small offline heuristic over function words and letters English does not use, currently covering Portuguese against English ([mixed_language.py](../harness/mixed_language.py)). It never touches the network and never loads a model. When a passage is too short or too mixed to call, it reports nothing rather than blocking a send; short openings and closings are decided by their greeting words instead. It reports paragraph positions, never the text, so the lane ledger holds no part of a private draft.

Lint checks question count, links, recent contact collisions and similarity across drafts. It normalizes names, links and titles; first/last sentence word-set Jaccard thresholds are 0.6 and body 5-gram Jaccard is 0.35. Similarity is reported as a **warning** and never fails a draft: two emails sharing a conventional greeting or sign-off is normal, and the two-language rule above makes a shared sign-off likelier still. The voice check is what guards against a templated message. These heuristics can miss templated spam or flag legitimate messages. A documented collision override is possible, and `sent --utc` records a message that went out before the ledger caught up.

Approval requires a current passing lint hash and the operator's approval quote. Any byte change invalidates approval. `sent` requires matching approved bytes and records a message identifier; follow-ups become due after the configured interval. The optional email hook checks exact submitted bytes against the latest approved ledger entry. Approval enforcement defaults to warning; set `RH_OUTREACH_GATE=enforce` in the sending environment. Voice failures deny in both modes. The hook cannot authenticate the person behind an approval quote and matches message bodies, not recipient authorization.
